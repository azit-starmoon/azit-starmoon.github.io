# AZIT : Star&Moon

마음의 지도를 그려 보는 상담 검사실이에요.
승인된 상담사가 구글 계정으로 로그인해 검사자에게 검사를 진행하고, 결과는 상담사 계정으로 전송돼요.
검사자는 결과를 바로 보지 않고, 상담사가 '검사 결과'에서 따로 열어 봐요.

- 사이트: https://azit-starmoon.github.io/
- 호스팅: GitHub Pages (이 저장소의 `main` 브랜치 루트)
- 로그인과 저장: Firebase Authentication(구글) + Realtime Database (`azit-starmoon` 프로젝트)

- 한국형 성향검사는 아홉 유형 이론(에니어그램)을 바탕으로 한 검사예요. 2부는 1부에서 가장 높게 나온 세 유형의 동기(두려움, 바라는 것, 주의, 아픈 말, 힘들 때, 듣고 싶은 말)를 서로 맞대는 적응형 문항이고, 최종 점수는 1부 45%, 2부 55%로 합쳐요. 문항과 해설은 이 사이트를 위해 새로 썼어요.
- 삶의 규칙 검사는 심리도식 이론의 18가지 도식, 다섯 영역, 세 가지 대처 방식(굴복, 회피, 과잉보상)을 바탕으로 문항과 해설을 새로 썼어요. 도식마다 5문항(6점 척도)의 평균과 '그렇다' 이상으로 답한 문항 수를 함께 보고 강함, 작동, 약간, 낮음으로 나눠요. 점수는 규준 비교가 아니라 응답 그대로의 세기예요. 같은 도식 문항끼리 응답이 크게 엇갈리면 응답 점검에서 알려 줘요.
- 애착 유형 검사는 성인 애착의 두 축(불안, 회피) 이론을 바탕으로 문항과 해설을 새로 썼어요. 두 축을 0~100으로 환산해 50을 넘는지로 네 유형을 나누고, 가운데에서 8점 안쪽이면 이웃 유형과의 경계로 알려 줘요. 관계별 지도는 대상마다 6문항이고 건너뛸 수 있어요. 결과지 끝의 '상담에서 함께 볼 것'은 상담사용 메모라서 공유 링크로 여는 결과지에는 나오지 않아요.
- 초민감성 검사는 감각처리민감성 이론의 네 갈래(DOES)를 바탕으로 문항과 해설을 새로 썼어요. 갈래마다 10문항(그중 3문항은 반대 방향, 5점 척도)이고, 0~100으로 환산해 75 이상 매우 높음, 62 이상 높음, 38 미만 낮음으로 읽어요(집단 규준이 아니라 문항 평균 기준). 전체가 높음 이상이면 흔히 HSP라고 부르는 범위예요. 2부 '요즘의 나'는 최근 2주의 부담 신호와 회복 자원으로 네 상태(과부하, 버티는 중, 잘 피어나는 중, 채움이 필요함)를 그려요. 응답 점검 기준은 시뮬레이션으로 정했어요(`tests/hsp/scoring.js`).
- 성격 강점 검사는 긍정심리학의 성격 강점 분류(6덕목, 24강점)를 바탕으로 문항과 해설을 새로 썼어요(기존 강점 척도의 문항은 쓰지 않았어요). 강점마다 4문항(그중 1문항은 반대 방향, 5점 척도)이고 1부와 2부에 2문항씩 나눠 실었어요. 점수는 0~100으로 환산하지만 결과는 내 안에서의 순위로 읽어요(1~5위 대표 강점, 20~24위 덜 쓰는 강점). 응답 점검 기준은 시뮬레이션으로 정했어요(`tests/strengths/scoring.js`).
- 가치관 검사는 Schwartz의 10가지 기본 가치와 원형 구조를 바탕으로 문항과 해설을 새로 썼어요(기존 가치 척도의 문항은 쓰지 않았어요). 짧은 글 속 사람이 나와 얼마나 닮았는지 6점으로 답하고, 가치마다 4문항(그중 1문항은 반대 방향)이에요. 사람마다 답을 후하게 또는 짜게 주는 버릇을 지우려고 각 가치 평균에서 40문항 전체 평균을 뺀 값으로 순위를 세워요(1~3위 핵심 가치). 맞은편 두 가치가 함께 높으면 가치 갈등으로 알려 줘요. 응답 점검 기준은 시뮬레이션으로 정했어요(`tests/values/scoring.js`).
- 진로 흥미 검사는 Holland의 직업 흥미 여섯 유형(RIASEC)과 육각형 구조를 바탕으로 문항과 해설을 새로 썼어요(기존 흥미 검사의 문항은 쓰지 않았어요). 유형마다 10문항(1부 활동 5, 2부 일터 5, 그중 3문항은 반대 방향, 5점 척도)이고, 점수가 높은 세 유형으로 흥미 코드를 만들어요. 첫째·둘째 흥미가 육각형에서 얼마나 가까운지(일관도), 가장 높은 흥미와 낮은 흥미의 차이(변별도), 여섯 흥미의 평균(흥미 수준)을 함께 보여 줘요. 직업 예시는 탐색의 출발점이에요. 응답 점검 기준은 시뮬레이션으로 정했어요(`tests/career/scoring.js`).
- 빅파이브 성격검사는 저작권 없는 공개 문항 풀 IPIP의 120문항 구성(하위 요인 30개 × 4문항)을 한국어로 옮겼어요. '가치 개방성' 하위 요인은 원문의 미국 정치 문항 대신 관습과 권위에 대한 태도를 묻는 문항으로 바꿨어요. 점수는 응답을 0~100으로 환산한 값이고, 60 초과는 높음, 40 미만은 낮음으로 읽어요(표준화 규준이 아니라 척도 중앙값 기준).

## 처음 설정 (한 번만)

1. Firebase 콘솔 → Authentication → 로그인 방법 → **Google 사용**
2. Authentication → 설정 → 승인된 도메인 → `azit-starmoon.github.io` 추가
3. Realtime Database → 규칙 → [`firebase/database.rules.json`](firebase/database.rules.json) 내용을 붙여넣고 **게시**
4. 사이트에 구글로 로그인 → 주소창에 `admin.html`을 열고 → **이 계정을 첫 관리자로 등록하기**
   - 관리자가 한 명도 없을 때만 등록돼요. 그래서 사이트를 연 사람이 가장 먼저 해야 해요.
   - 관리자 계정은 승인 없이 바로 이용할 수 있어요.
   - 이후 관리자는 관리 페이지의 **관리자 지정**에서 다른 사람을 추가하거나 해제할 수 있어요.

## 이용 흐름

1. **로그인** (`login.html`): 구글로 로그인해요. 승인되지 않은 계정은 이름과 소속(선택)을 적어 **요청 보내기**를 눌러요.
2. **승인**: 관리자가 관리 페이지의 **승인 요청**에서 승인하거나 거절해요. 승인된 계정은 **승인된 상담사** 목록에 올라가고, 언제든 승인을 취소할 수 있어요.
3. **첫 화면**: "반갑습니다 ○○○ 상담사님!" 인사와 함께 **검사 코드**를 넣으면 검사 목록이 열려요. 이름은 승인 요청에 적은 이름을 써요.
4. **검사**: 시작할 때마다 **검사자 이름**을 새로 적어요. 한 계정으로 여러 사람을 검사할 수 있어요. 답할 때마다 자동으로 저장되고(문항 위 '✓ 저장됨'), 멈춘 검사는 첫 화면 인사 바로 아래 **이어서 할 검사**에서 이어 가요.
5. **끝**: 결과 대신 "검사 결과가 전송되었습니다"가 떠요. **다음 검사 시작하기**나 **처음으로**만 있고, 결과로 가는 길은 없어요.
6. **검사 결과** (`me.html`): **결과 잠금 번호**를 넣으면 열려요. 검사자 이름으로 찾아 결과지를 열고, 공유 링크를 만들거나 지워요.

## 권한

| 누가 | 할 수 있는 것 |
|---|---|
| 승인 전 계정 | 승인 요청 보내기·취소하기 (검사와 결과에는 들어갈 수 없음) |
| 승인된 상담사 | 검사 진행, 자기 계정으로 전송된 결과 보기, 공유 링크 만들기·멈추기, 결과 지우기 |
| 관리자 | 상담사 승인·거절·승인 취소, 모든 결과 보기, 어떤 결과든 공유·지우기, CSV 내려받기, 관리자 지정 |
| 공유 링크를 받은 사람 | 로그인 없이 그 결과지 하나만 보기 |

승인 여부는 화면뿐 아니라 Realtime Database 보안 규칙에서도 막아요. 승인이 취소된 계정은 더 이상 결과를 저장하거나 읽을 수 없고, 이미 저장된 결과는 관리자가 계속 볼 수 있어요.

## 진행 저장과 이어하기

- 답할 때마다 진행 상황이 **그 기기**와 **상담사 계정**(`drafts`) 두 곳에 저장돼요. 검사 중에는 문항 위에 '✓ 저장됨'이 보이고, 누르면 어디에 저장되는지 알려 줘요.
- 검사자마다 따로 저장되어서, 다른 검사자로 새로 시작해도 앞사람 기록이 지워지지 않아요. 같은 이름으로 다시 시작하면 '하다 멈춘 검사가 있어요'라고 먼저 물어봐요.
- 멈춘 검사는 첫 화면 인사 바로 아래 **이어서 할 검사**와 각 검사 소개 화면 맨 위에 보여요. 누르면 멈춘 문항부터 바로 이어져요. 검사 중 새로고침해도 그 자리로 돌아와요.
- 상단의 **저장하고 나가기**를 누르면 마지막 답까지 저장한 뒤 첫 화면으로 가요.
- 계정에 저장된 기록 덕분에 휴대폰에서 하다가 PC에서 이어 갈 수 있어요. 데이터베이스 규칙에 `drafts`가 없으면 그 기기 안에서만 이어져요.
- 끝내지 않은 기록은 30일이 지나면 지워지고, 검사를 끝내면 바로 지워져요.

## 새 버전 알림

- 사이트를 고쳐 올릴 때마다 `python3 tools/stamp-version.py`로 `version.json`을 바꿔요.
- 사용하던 화면이 예전 파일로 그려졌으면 아래에 **새 버전이 올라왔어요 [새로고침]**이 떠요. 검사 중이면 저장한 뒤 같은 문항으로 다시 열려요.

## 점검

- `python3 tools/smoke.py`: 체험 모드로 모든 검사를 끝까지 진행하고, 저장·이어하기, 결과지 목차와 스크롤, 관리 화면까지 한 바퀴 확인해요. 문제가 있으면 종료 코드 1.
- 새 검사를 만드는 방법과 자동 작업 규칙은 `docs/NEW_TEST.md`에 있어요.

## 화면 잠금

| 잠금 | 걸리는 곳 | 다시 잠기는 때 |
|---|---|---|
| 검사 코드 | 첫 화면(검사 목록), 검사 화면 | 그 탭을 닫을 때, 로그아웃할 때, 12시간이 지났을 때 |

- 5번 틀리면 30초 동안 입력할 수 없어요.
- 공유 링크로 여는 결과지는 잠그지 않아요.
- 이 잠금은 상담사 기기를 검사자에게 건넬 때를 위한 화면 잠금이에요. 데이터는 로그인과 승인(보안 규칙)이 서버에서 지켜요.
- 번호는 사이트 코드에 그대로 두지 않고 SHA-256 값만 둬요(`assets/js/config.js`의 `LOCKS`). 번호를 바꾸려면 아래처럼 새 값을 만들어 바꿔 넣어요.
  ```
  node -e "console.log(require('crypto').createHash('sha256').update('azit-starmoon:test:<새 번호>').digest('hex'))"
  node -e "console.log(require('crypto').createHash('sha256').update('azit-starmoon:result:<새 번호>').digest('hex'))"
  ```

## 체험 모드

주소 끝에 `?demo=1`을 붙이면 Firebase 없이 이 기기 안에서만 로그인과 저장이 동작해요. 화면 위에 노란 띠가 보이면 체험 모드예요.
`?demo=0`을 붙이면 원래대로 돌아와요.
체험 모드에서 `?demorole=user`를 붙이면 승인 전 계정처럼, `?demorole=admin`을 붙이면 관리자처럼 움직여요.

## 새 검사를 추가할 때

1. `tests/<검사 id>/index.js`에서 아래 모양의 객체를 내보내요.
   - `id`, `version`, `title`, `intro`
   - `parts`: 부마다 `kind`(`likert` / `pair` / `rank`), `items` 또는 `build(answers)`, `count`
     (선택) `label` 부 번호 대신 보일 글, `skippable` 건너뛰기 버튼, `skipLabel`, `enterLabel`. 건너뛴 문항은 `null`로 저장돼요.
   - `score(answers, meta)`, `summary(scores)`, `glyph(scores)`, `render(element, record, ctx)`
2. `assets/js/registry.js`에서 그 검사의 `status`를 `'open'`으로 바꿔요.

자세한 순서와 품질 기준은 `docs/NEW_TEST.md`를 따라요. 진행 화면, 로그인과 승인, 저장, 결과 공유, 관리자 화면은 공통이라 따로 만들 필요가 없어요.
